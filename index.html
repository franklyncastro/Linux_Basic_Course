Estructura del sistema de archivos
FHS · Directorios críticos · Navegación básica
▼
Teoría
Linux usa el FHS (Filesystem Hierarchy Standard). Todo parte desde / (la raíz). Los directorios más importantes:

/etc — Archivos de configuración del sistema
/var — Datos variables: logs, colas, bases de datos en ejecución
/home — Carpetas de usuarios (/home/franklyn)
/bin, /usr/bin — Programas ejecutables
/sbin, /usr/sbin — Comandos de administración (requieren root)
/tmp — Archivos temporales, se borran al reiniciar
/proc — Sistema virtual: información del kernel y procesos en tiempo real
/dev — Dispositivos de hardware representados como archivos
/mnt, /media — Puntos de montaje para discos y USB
Comandos esenciales
BASHNavegación
# ¿Dónde estoy? pwd # Listar archivos con detalles ls -la # Ir a la raíz cd / # Ir a mi home cd ~ # Subir un directorio cd .. # Ver árbol de directorios tree / -L 2 # ¿Qué tipo de archivo es este? file /etc/passwd
Ejercicio práctico
Mapa mental del servidor
  1. Abre Kali Linux en VirtualBox y abre una terminal
  2. Escribe cd / y luego ls -la — observa todos los directorios
  3. Entra a cada directorio importante: cd /etc && ls | head -20
  4. Haz lo mismo con /var/log y /proc
  5. Guarda el árbol: tree / -L 2 > ~/mapa_sistema.txt
  6. Léelo: cat ~/mapa_sistema.txt | less — navega con flechas, sal con q
Tip profesional
En un trabajo real, lo primero que harás en un servidor nuevo es explorar /etc y /var/log. Memorizar esta estructura te ahorrará horas de búsqueda.

3
Usuarios, grupos y permisos
chmod · chown · sudo · useradd · passwd
▼
Teoría
Los permisos se dividen en 3 categorías: propietario (u), grupo (g) y otros (o). Cada uno puede tener lectura (r=4), escritura (w=2) y ejecución (x=1).

Cuando ves -rwxr-xr--:
— rwx = dueño puede leer, escribir, ejecutar
— r-x = grupo puede leer y ejecutar
— r-- = otros solo pueden leer

En octal: rwx=7, r-x=5, r--=4, rw-=6, ---=0
Comandos esenciales
BASHPermisos y usuarios
# Ver permisos ls -la archivo.sh # Cambiar permisos (octal) chmod 755 script.sh # rwxr-xr-x chmod 644 config.conf # rw-r--r-- chmod 600 clave.txt # rw------- (solo el dueño) # Cambiar propietario chown usuario:grupo archivo.txt chown -R www-data:www-data /var/www/ # Crear usuario sudo useradd -m -s /bin/bash juan sudo passwd juan # Ver grupos de un usuario groups franklyn id franklyn
Ejercicio práctico
Laboratorio de permisos
  1. Crea un script: echo "echo Hola Linux" > ~/test.sh
  2. Intenta ejecutarlo: ./test.sh — verás "Permission denied"
  3. Dale permisos: chmod +x ~/test.sh y vuelve a ejecutarlo
  4. Verifica permisos: ls -la ~/test.sh
  5. Crea usuario de prueba: sudo useradd -m testuser && sudo passwd testuser
  6. Cambia dueño: sudo chown testuser ~/test.sh — intenta editarlo

Gestión de procesos
ps · top · htop · kill · systemctl
▼
Teoría
Un proceso es un programa en ejecución. Cada proceso tiene un PID (Process ID). En un servidor de aplicaciones, monitorear procesos es parte del trabajo diario. systemd es el gestor de servicios moderno — con systemctl controlas todos los servicios del sistema.
Comandos esenciales
BASHProcesos y servicios
# Ver todos los procesos ps aux ps aux | grep apache # Monitor en tiempo real top htop # Matar proceso por PID kill 1234 kill -9 1234 # forzar (SIGKILL) # Matar por nombre pkill firefox killall nginx # Servicios con systemctl sudo systemctl status ssh sudo systemctl start ssh sudo systemctl stop ssh sudo systemctl restart ssh sudo systemctl enable ssh # iniciar al boot # Ver todos los servicios systemctl list-units --type=service
Ejercicio práctico
Monitor de servidor simulado
  1. Ejecuta top — observa %CPU, %MEM, estados (S=sleep, R=running, Z=zombie)
  2. Sal con q, instala htop: sudo apt install htop -y
  3. Ejecuta htop — navega con F5 (árbol), F9 (kill), F10 (salir)
  4. Inicia SSH: sudo systemctl start ssh
  5. Verifica: sudo systemctl status ssh
  6. Busca su PID: ps aux | grep sshd

Gestión de discos y almacenamiento
df · du · fdisk · mount · lsblk
▼
Teoría
Monitorear el espacio en disco es una de las tareas más críticas. Un disco lleno puede tumbar aplicaciones y bases de datos completas. Debes saber identificar qué está consumiendo espacio y cómo montar/desmontar sistemas de archivos.
Comandos esenciales
BASHDisco y almacenamiento
# Ver espacio en discos montados df -h # Ver tamaño de directorios du -sh /var/log du -sh /* 2>/dev/null | sort -rh | head -10 # Ver dispositivos de bloque lsblk # Ver particiones sudo fdisk -l # Montar una partición sudo mount /dev/sdb1 /mnt/datos # Desmontar sudo umount /mnt/datos # Encontrar archivos grandes find / -size +100M -type f 2>/dev/null
Ejercicio práctico
Auditoría de espacio en disco
  1. Ejecuta df -h — identifica la partición con menos espacio
  2. Los 10 dirs más grandes: sudo du -sh /* 2>/dev/null | sort -rh | head -10
  3. Revisa logs: du -sh /var/log/*
  4. Archivos >10MB: find / -size +10M -type f 2>/dev/null
  5. Documenta: df -h > ~/reporte_disco.txt && du -sh /* 2>/dev/null >> ~/reporte_disco.txt

▼
Teoría
Kali/Debian usan APT (Advanced Package Tool). En entornos empresariales con RedHat/CentOS usarás yum/dnf, pero la lógica es igual. Saber instalar, actualizar y remover paquetes es fundamental para cualquier admin.

BASHAPT

Ejercicio práctico
Setup de herramientas de administración
  1. Actualiza el sistema: sudo apt update && sudo apt upgrade -y

  3. Instala nginx: sudo apt install nginx -y && sudo systemctl start nginx
  4. Verifica: curl http://localhost — deberías ver HTML de nginx
  5. Verifica versión: nginx -v

Fundamentos de Shell Scripting
Variables · echo · read · shebang
▼
Teoría
Un shell script es una secuencia de comandos guardada en un archivo. La primera línea siempre es el shebang (#!/bin/bash). Las variables en bash no tienen tipo — todo es texto por defecto. Para usar una variable se escribe $NOMBRE.
Tu primer script real
BASH SCRIPTVariables y I/O
#!/bin/bash NOMBRE="Franklyn" SERVIDOR="web-prod-01" FECHA=$(date +%Y-%m-%d) # comando como variable echo "Administrador: $NOMBRE" echo "Servidor: $SERVIDOR" echo "Fecha: $FECHA" # Leer input del usuario read -p "¿Tu nombre? " USUARIO echo "Hola, $USUARIO" # Variables especiales echo "Script: $0" echo "Argumento 1: $1" echo "Total args: $#" echo "PID del script: $$"

Condicionales
if · elif · else · test · operadores
▼
Teoría
En bash, [ ] y [[ ]] evalúan condiciones. Los operadores numéricos son: -eq (igual), -ne (diferente), -gt (mayor), -lt (menor), -ge (mayor o igual), -le (menor o igual). Para archivos: -f (existe y es archivo), -d (es directorio), -x (es ejecutable).
Condicionales en bash
BASH SCRIPTif/elif/else
#!/bin/bash ESPACIO=$(df / | tail -1 | awk '{print $5}' | tr -d '%') if [ $ESPACIO -gt 90 ]; then echo "ALERTA: Disco al $ESPACIO% — crítico" elif [ $ESPACIO -gt 70 ]; then echo "AVISO: Disco al $ESPACIO% — vigilar" else echo "OK: Disco al $ESPACIO%" fi # Verificar si servicio está corriendo if systemctl is-active --quiet nginx; then echo "nginx: RUNNING" else echo "nginx: STOPPED" systemctl start nginx fi # Verificar si archivo existe if [ -f /etc/nginx/nginx.conf ]; then echo "Config nginx encontrada" fi

Script profesional integrador para la entrevista

Script de KPIs completo
BASH SCRIPTkpi_report.sh
#!/bin/bash FECHA=$(date '+%Y-%m-%d %H:%M:%S') REPORTE="/tmp/kpi_$(date +%Y%m%d_%H%M).txt" log() { echo "[${FECHA}] [$1] $2" | tee -a $REPORTE; } log "INFO" "===== KPI — SERVIDOR: $(hostname) =====" CPU=$(top -bn1 | grep "Cpu(s)" | awk '{print $2}' | tr -d '%us,') log "KPI" "CPU Usage: ${CPU}%" MEM_TOTAL=$(free -m | awk '/Mem/{print $2}') MEM_USED=$(free -m | awk '/Mem/{print $3}') MEM_PCT=$((MEM_USED * 100 / MEM_TOTAL)) log "KPI" "Memory: ${MEM_USED}MB/${MEM_TOTAL}MB (${MEM_PCT}%)" df -h | awk 'NR>1' | while read line; do PART=$(echo $line | awk '{print $1}') USO=$(echo $line | awk '{print $5}') log "KPI" "Disco $PART: $USO" done for SVC in ssh cron nginx; do STATUS=$(systemctl is-active $SVC 2>/dev/null) log "SVC" "$SVC: $STATUS" done log "INFO" "Top procesos CPU:" ps aux --sort=-%cpu | awk 'NR>1&&NR<=4{printf " %-10s CPU:%s%% MEM:%s%%\n",$1,$3,$4}' \ | tee -a $REPORTE log "INFO" "Reporte: $REPORTE"
